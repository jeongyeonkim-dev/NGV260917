# A-SPICE 4.1 SWE.6 베이스프랙티스 근거

> 출처: VDA QMC, *Automotive SPICE® PAM*, Version 4.1(예비판, 2026-04-16), §4.4.6(SWE.6). 영문 원문을 한국어로 옮기고 체크포인트를 덧붙였다.

## SWE.6 — 소프트웨어 검증 (Software Verification)

**목적**: 통합된 소프트웨어가 소프트웨어 요구사항과 일관됨을 검증한다.

**성과항목(Outcome)**
1. 소프트웨어 요구사항에 근거해 소프트웨어 검증을 위한 검증측정이 명세된다.
2. 회귀검증 기준을 포함한 선정기준에 따라 검증측정이 선정된다.
3. 선정된 검증측정으로 통합된 소프트웨어가 검증되고, 소프트웨어 검증 결과가 기록된다.
4. 검증측정과 소프트웨어 요구사항 간 일관성과 양방향 추적성이 수립된다.
5. 검증결과와 검증측정 간 양방향 추적성이 수립된다.
6. 소프트웨어 검증 결과가 요약되어 이해관계자에게 전달된다.

**베이스프랙티스**
- **BP1 — 소프트웨어 검증을 위한 검증측정 명세**: 통합된 소프트웨어가 기능·비기능 소프트웨어 요구사항을 준수함을 입증할 수 있는 검증측정을 명세한다. 기법, 통과/실패 기준, 진입/종료 기준, 필요한 순서, 검증 인프라·환경을 포함한다.
  - **참고(이 스킬의 핵심 근거)**: 검증측정에 적합한 기법의 선택은 해당 소프트웨어 요구사항의 내용에 따라 달라질 수 있다 — 예를 들어 데이터 범위 지향 요구사항에는 경계값과 동등분할, 긍정(sunny-day) 시험 대 부정 시험(결함주입 등), 또는 요구사항기반시험 대 "지식·경험에 근거한 오류추측" 중에서 선택한다.
- **BP2 — 검증측정 선정**: 회귀검증 기준을 포함한 선정기준을 고려해 검증측정의 선정을 문서화한다. 선정된 검증측정은 릴리스 범위에 따라 충분한 커버리지를 가져야 한다.
- **BP3 — 통합된 소프트웨어 검증**: 선정된 검증측정으로 통합된 소프트웨어의 검증을 수행한다. 통과/실패 상태와 해당 검증측정 데이터를 포함해 결과를 기록한다.
- **BP4 — 일관성 확보 및 양방향 추적성 수립**: 검증측정과 소프트웨어 요구사항 간 일관성과 양방향 추적성을 확보한다. 검증결과와 검증측정 간 양방향 추적성도 수립한다.
  - 참고: 추적 링크의 존재 자체가 정보의 일관성을 의미하지는 않는다.
- **BP5 — 결과 요약 및 전달**: 소프트웨어 검증 결과를 요약해 모든 이해관계자에게 전달한다.

**출력 산출물**: 08-60 검증측정(Verification Measure), 03-50 검증측정 데이터, 08-58 검증측정 선정 세트, 15-52 검증 결과, 13-51 일관성 증적, 13-52 커뮤니케이션 증적

## SWE.4/SWE.5와의 경계 (재확인)
- SWE.4(소프트웨어 단위 검증)는 상세설계 단위 인터페이스가 테스트 베이시스다 — `tdd` 스킬이 구현 단계에서 담당한다.
- SWE.5(소프트웨어 컴포넌트 검증 및 통합검증)는 아키텍처의 컴포넌트 인터페이스·통합순서가 테스트 베이시스다 — `integration-testing` 스킬이 담당한다.
- **SWE.6(이 스킬)은 소프트웨어 요구사항이 테스트 베이시스다** — 이미 통합이 끝난 소프트웨어 전체를 블랙박스로 검증한다. 컴포넌트 내부 구조나 인터페이스 자체를 시험 대상으로 삼지 않는다.
