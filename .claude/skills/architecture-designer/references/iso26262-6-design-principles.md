# ISO 26262-6 Clause 7 소프트웨어 아키텍처 설계원칙 (요약·재구성)

> 근거: ISO 26262-6:2018, Clause 7 "Software architectural design"(소프트웨어 아키텍처 설계), 특히 설계원칙 표(Table 3)와 인터페이스·표기법 관련 요구사항. **아래 내용은 표준 원문의 verbatim 인용이 아니라 요지를 한국어로 재구성한 것**이다 — ISO 26262는 저작권이 있는 유료 표준이므로, 인증심사·법적 근거가 필요한 경우 반드시 조직이 보유한 정본 Clause 7과 조항번호를 대조 확인한다.

## 설계원칙 (Table 3 요지)

| 원칙 | 요지 | 이 스킬에서의 적용 |
|------|------|----------------------|
| 계층적 구조 | 소프트웨어 아키텍처 요소를 계층 구조로 표현한다 | 컴포넌트 → 서브컴포넌트 → 단위(unit) 계층을 명확히 구분 |
| 제한된 크기·복잡도 | 컴포넌트 크기와 복잡도를 제한한다 | 하나의 컴포넌트가 과도하게 커지면 분할(God Component 금지) |
| **높은 응집도** | 컴포넌트 내부 요소가 하나의 목적을 위해 강하게 협력해야 한다 | SKILL.md 3단계 필수 점검 항목 |
| **낮은 결합도** | 컴포넌트 간 의존을 최소화한다 | SKILL.md 3~4단계 필수 점검 항목, 순환 의존 금지 |
| 적절한 스케줄링 속성 | 실행 순서가 데이터 가용 시점과 일치해야 한다(예: 센서값 변환 완료 후 처리) | 5단계 동적 설계에서 타이밍 제약으로 반영 |
| 인터럽트 사용 제한 | 인터럽트 남용은 스케줄링을 교란하고 예측 불가능한 동작을 유발할 수 있어 폴링 등 대안을 우선 검토 | 실시간성이 중요한 컴포넌트의 인터페이스/동적 설계 시 고려 |
| 포인터 사용 제한 | 포인터 오용은 결합도를 높이고 결함을 유발하기 쉽다 | 인터페이스는 값/참조 계약을 명시적으로 정의(수신자가 임의 포인터 연산을 하지 않도록) |
| 동적 객체/변수 사용 제한(또는 온라인 테스트) | 런타임 동적 할당은 예측 불가능성을 높인다 | 자원 제약이 있는 컴포넌트의 인터페이스 설계 시 정적 할당 우선 검토 |
| 재귀 사용 제한 | 재귀는 스택 사용량 예측을 어렵게 한다 | 임베디드 대상 컴포넌트 설계 시 반복문 대안 검토 |
| 공간적 분리(2018 신설) | 안전 관련 요소와 비안전 요소를 공간적으로 분리(예: 메모리 보호) | ASIL이 다른 컴포넌트 간 경계 설계 시 반영 |
| 공유자원의 적절한 관리(2018 신설) | 공유자원(메모리, 버스, 스케줄러 등) 접근을 통제해 간섭을 방지한다 | 인터페이스에 자원 접근 프로토콜(잠금, 우선순위)을 명시 |

## 인터페이스 정의 요구사항 (Clause 7.4.x 요지)

컴포넌트 간 교환되는 데이터의 종류와 양을 제한해야 결함 전파 위험이 줄어들고, 이는 FTA/FMEA 같은 안전분석의 전제가 된다. 인터페이스 정의에는 최소한 다음이 포함되어야 한다:

- 오퍼레이션/시그널의 이름과 방향(제공/요구)
- 데이터 타입, 유효범위(range), 단위(unit), 정밀도
- 호출/전송 순서 및 타이밍 제약
- 오류·예외 상황의 처리 방식

이 내용은 `references/interface-first-design.md`의 인터페이스 명세 필수 항목과 직접 대응한다.

## 설계 표기법 (정적/동적 측면, 표기법 표 요지)

- **정적 측면**: 계층 구조, 데이터 타입, 인터페이스를 표현.
- **동적 측면**: 제어 흐름, 시간적 제약, 동시성(concurrency)을 표현.
- **표기법 3종**: 비정형(자연어), 반정형(다이어그램 — 데이터흐름도, 시퀀스 다이어그램, UML/SysML 등), 정형(수학적 표현 — 정형 검증이 가능한 모델). ASIL이 높을수록 반정형·정형 표기의 사용이 권장된다. `requirements-analyst` 스킬의 `references/uml-sysml-notation.md`와 동일한 다이어그램 표기 원칙(요소에 ID 라벨링, 표준 표기 준수)을 이 스킬에서도 그대로 적용한다.

## 이 스킬에서 "필수"로 격상한 항목
사용자 요구에 따라 아래 두 원칙은 다른 원칙보다 우선순위를 높여, 위반 시 다음 단계로 진행하지 않고 재설계한다:
1. 높은 응집도 / 낮은 결합도
2. 컴포넌트 간 통신은 정의된 인터페이스를 통해서만 이루어짐(암묵적 결합 금지)
