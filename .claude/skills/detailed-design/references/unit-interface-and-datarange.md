# 단위 인터페이스·데이터 유효범위 명세 체크리스트

> `architecture-designer` 스킬의 `interface-first-design.md`를 소프트웨어 단위 수준으로 확장한 것이다. 컴포넌트 수준 인터페이스 규칙(모든 통신은 정의된 인터페이스로만, 방향·타입·타이밍·오류처리 명시)은 단위 수준에서도 그대로 유효하다. 여기서는 SWE.3.BP1이 요구하는 **유효 데이터 값 범위·물리단위** 명시를 추가한다.

## 단위 인터페이스 명세 필수 항목

| 항목 | 설명 |
|------|------|
| 이름 | 단위(함수/서브루틴)명, 파라미터명 |
| 방향 | 입력 / 출력 / 입출력(in-out) |
| 데이터 타입 | 프로그래밍 언어 수준 타입(예: `uint16_t`) |
| **유효 데이터 값 범위** | 응용영역 관점의 최소~최대값(예: `0..200`) — SWE.3.BP1 필수 |
| **물리/측정 단위** | 있는 경우 명시(예: `m/s`, `%`, `°C`), 없으면 "단위 없음"으로 명시 |
| 정밀도/분해능 | 필요 시 소수점 자리, 양자화 단위 |
| 오류·예외 처리 | 유효범위를 벗어난 값 수신 시 동작(반환코드, 클램핑, 안전상태 전이 등) |
| 사전조건/사후조건 | 설계에 의한 계약(design-by-contract) — 호출 전 보장되어야 할 조건, 호출 후 보장하는 조건 |

## 값 범위 매핑 점검
- 응용영역 값 범위(예: `0..200 [m/s]`)가 프로그래밍 언어 타입의 표현 범위(예: `uint16_t`의 `0..65535`) 안에 안전하게 들어가는지 확인한다.
- 언어 타입 범위가 응용영역 범위보다 훨씬 넓다면(예: 위 예시), 방어적 검사(범위검사)로 응용영역 범위를 벗어난 값을 차단하는 로직이 설계에 포함되어야 한다(`iso26262-6-unit-design-principles.md`의 "범위검사·방어적 프로그래밍" 원칙).
- 카운터처럼 물리단위가 없는 파라미터는 빠뜨리지 말고 "단위 없음"으로 명시적으로 표기한다 — 표기 누락과 "단위 없음"은 다르다(전자는 미완성, 후자는 검토 완료).

## 인터페이스 우회 금지 (컴포넌트 수준 규칙의 단위 수준 적용)
- 같은 컴포넌트 내부의 단위끼리는 상대적으로 결합이 자유로울 수 있으나(내부 응집), **다른 컴포넌트에 속한 단위를 직접 호출하거나 그 내부 자료구조에 접근하는 것은 금지**한다 — 반드시 컴포넌트 인터페이스를 통해서만 접근한다.
- 전역변수를 통한 단위 간 암묵적 데이터 공유는 금지한다. 공유가 꼭 필요하면 명시적 인터페이스(접근자 함수 등)로 감싼다.
