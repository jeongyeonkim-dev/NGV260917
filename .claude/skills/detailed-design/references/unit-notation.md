# 상세설계 표기법 가이드

상세설계 문서는 구현자가 추가 질문 없이 코드를 작성할 수 있을 정도로 구체적이어야 한다(SKILL.md 6단계 이해가능성 검토와 연결). `architecture-designer` 스킬의 `uml-sysml-notation.md`와 마찬가지로, 다이어그램은 텍스트 설계를 보완하는 것이지 대체하지 않는다 — 모든 다이어그램 요소에 대응하는 단위 ID를 라벨링한다.

## 설계 성격별 표기법 선택

| 설계 성격 | 권장 표기법 | 용도 |
|------------|--------------|------|
| 순차·조건·반복 로직 | 의사코드(Pseudocode) 또는 흐름도(Flowchart) | 알고리즘 단계를 구현 언어와 무관하게 명확히 서술 |
| 단위 간 호출 순서 | UML 시퀀스 다이어그램 | 여러 단위가 협력하는 시나리오의 호출 순서·타이밍 |
| 모드/상태 기반 동작 | UML/SysML 상태기계 다이어그램 | 단위 내부 상태 전이, 특히 안전 관련 상태 전이 |
| 정적 구조(클래스/구조체 관계) | UML 클래스 다이어그램 | 객체지향/구조체 기반 설계의 데이터 관계 |
| 복잡한 조건 조합 | 결정 테이블(Decision Table) | 다중 조건 분기를 표/행렬로 명확히 표현(구조적 제어흐름 원칙과도 부합) |

## 작성 원칙
1. **언어 종속 지양**: 상세설계는 특정 프로그래밍 언어의 문법에 얽매이지 않는 의사코드/다이어그램으로 표현하는 것을 기본으로 한다(단, 언어별 코딩 가이드라인 적용 여부는 별도로 명시).
2. **범위·단위 표기 동반**: 흐름도나 의사코드에 값이 등장하면, 그 값의 유효범위·물리단위를 주석으로 함께 표기한다(`unit-interface-and-datarange.md`와 연결).
3. **단위 ID 라벨링**: 다이어그램의 각 블록/스텝에 대응하는 단위 ID를 표기해 추적성을 유지한다.
4. **과도한 복잡도 지양**: 하나의 흐름도/의사코드 블록이 한 화면을 넘어가면 분할한다(순환복잡도 관리와 연결).
5. **파일 관리**: 다이어그램/의사코드 소스는 버전관리 가능한 텍스트 형식(PlantUML, Mermaid, 마크다운 표 등)을 기본으로 하고, `architecture-designer` 스킬의 다이어그램 저장 규칙을 그대로 따른다.
