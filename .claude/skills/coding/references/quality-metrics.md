# 품질지표 상세 정의 (CLAUDE.md 근거)

## 1. 함수 라인수 ≤ 50 (순수 코드라인)
- **정의**: 함수/메서드 하나의 본문에서 공백줄과 주석줄을 제외한 실행 코드 라인 수(SLOC, Source Lines of Code)가 50줄을 넘지 않는다.
- **판단 기준**: docstring도 "코드"가 아니라 문서이므로 순수 코드라인에서 제외한다.
- **초과 시 조치**: 함수가 여러 책임을 섞고 있다는 신호로 보고, 의미 단위로 분리한다(추출한 하위 함수도 같은 기준을 적용받는다).

## 2. 함수 순환 복잡도 ≤ 10
- **정의**: McCabe 순환복잡도(분기·반복·조건 연산자 등으로 늘어나는 독립 실행경로 수)가 함수당 10 이하.
- **판단 기준**: `if`/`elif`/`for`/`while`/`except`/`and`/`or`/삼항연산자 등 분기를 만드는 구조마다 복잡도가 증가한다.
- **초과 시 조치**: 가드절(guard clause)로 조기 반환, 중첩 depth 축소, 조건 로직을 별도 함수/전략 패턴으로 추출.

## 3. 중복 코드 7라인까지 허용
- **정의**: 서로 다른 위치에 등장하는 동일하거나 거의 동일한 코드 블록의 길이가 7라인 이하면 허용하고, **8라인 이상**이면 위반으로 처리한다.
- **판단 기준**: 도구 설정 시 `min-similarity-lines`(또는 동등 옵션)을 8로 설정해 8라인 이상만 검출되게 한다 — 기본값을 그대로 쓰면 임계값이 프로젝트 기준과 달라질 수 있으니 반드시 설정을 확인한다.
- **초과 시 조치**: 공통 로직을 함수/헬퍼 모듈로 추출하고, 호출부에서 재사용한다.

## 4. Doxygen 방식 주석, 20% 이상
- **정의**: 전체 코드에서 주석(및 Doxygen 스타일 docstring) 라인이 차지하는 비율이 20% 이상.
- **비율 계산**: `주석 비율 = 주석 라인 수 / (주석 라인 수 + 순수 코드라인 수)` — 공백줄은 분모·분자 모두에서 제외한다. 측정 도구가 다른 정의를 쓰면 이 정의에 맞춰 재계산한다.
- **작성 방식**: `references/doxygen-comment-convention.md`의 `@brief`/`@param`/`@return`/`@throws` 태그 규칙을 따른다.
- **주의**: 비율을 채우기 위해 의미 없는 주석("i를 1 증가시킨다" 같은 코드 재진술)을 채우지 않는다 — 사전/사후조건, 예외 상황, 설계 근거, 물리적 의미(단위·범위)처럼 코드만 봐서는 알 수 없는 정보를 우선 채운다. 그래도 비율이 부족하면 그 사실을 그대로 보고한다(가짜 주석으로 수치만 맞추지 않는다).

## 5. 네이밍 — 함수명·변수명 3글자 이상, 카멜케이스
- **정의**: 함수명과 변수명은 최소 3글자 이상이어야 하며, 카멜케이스(`myVariable`, `calcSpeed`)로 작성한다. 단일 글자 변수(`i`, `x`)나 두 글자 변수(`dt`)는 허용하지 않는다(반복문 인덱스도 예외 없이 3글자 이상 — 예: `idx`, `row`, `col`).
- **예외 처리**: 정말 불가피한 관례적 이름(예: 수학 공식의 `x`, `y` 좌표를 그대로 쓰는 경우)이 있다면, 예외 사유를 주석으로 남기고 팀 합의를 구한다 — 임의로 예외를 늘리지 않는다.
- **PEP8과의 관계**: Python 커뮤니티 관례(PEP8)는 스네이크케이스를 쓰지만, 이 프로젝트는 CLAUDE.md에 따라 **의도적으로** 카멜케이스를 쓴다. 외부 라이브러리·표준 라이브러리 API 자체의 이름(예: `self.assertEqual`)까지 바꾸는 것은 아니다 — 우리가 직접 작성하는 함수/변수명에 적용한다.

## 지표 간 상호작용
- 라인수·복잡도를 줄이려고 함수를 과도하게 쪼개면 오히려 함수 수가 많아지고 이름 짓기가 어려워질 수 있다 — 이 경우 응집도(하나의 함수가 하나의 의미 있는 작업을 하는지)를 기준으로 분리 지점을 정한다(`architecture-designer` 스킬의 SRP 논리를 함수 단위에 적용).
- 주석 비율을 맞추려다 코드 대비 주석이 과도해지면 오히려 가독성이 떨어질 수 있다 — 계약·근거 중심으로 작성해 자연스럽게 비율을 채운다.
