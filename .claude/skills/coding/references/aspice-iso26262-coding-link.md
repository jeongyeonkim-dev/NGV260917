# A-SPICE SWE.3.BP3 / ISO 26262-6 Clause 8과의 연결

이 스킬의 구현 규칙은 `detailed-design` 스킬이 이미 근거로 삼은 표준과 동일한 것을 코드 작성 시점에 실행하는 것이다. 중복 설명을 피하기 위해 원문·상세 표는 `detailed-design` 스킬의 `references/aspice-swe3-bp.md`, `references/iso26262-6-unit-design-principles.md`를 그대로 참조하고, 여기서는 "Python 구현에서 구체적으로 어떻게 지키는가"만 다룬다.

## SWE.3.BP3 — 코딩 원칙에 따른 단위 개발
- "암묵적 타입변환 미사용" → Python은 동적 타입 언어이므로, 타입힌트(`def foo(x: int) -> int:`)를 반드시 사용하고, 암묵적 형변환에 의존하는 연산(예: `bool`과 `int`의 혼용, 정수/실수 자동 승격을 이용한 로직)을 피한다. 필요한 변환은 `int(x)`, `float(x)`처럼 명시적으로 한다.
- "단일 진입점·단일 탈출점" → Python 함수에서 여러 개의 `return`이 가독성을 해치지 않는 범위(가드절 패턴)에서는 실용적으로 허용하되, 함수 중간에 예상치 못한 부작용(전역 상태 변경 후 조기 종료 등)이 숨어있지 않도록 한다 — 핵심은 "제어흐름이 코드를 읽는 것만으로 예측 가능한가"이다.
- "범위검사·방어적 프로그래밍" → `unit-interface-and-datarange.md`(detailed-design 스킬)에 정의된 유효범위를 함수 진입부에서 명시적으로 검사하고, 벗어나면 상세설계에 정의된 대로 예외를 던지거나 처리한다(`doxygen-comment-convention.md`의 `@throws` 예시 참조).

## ISO 26262-6 Clause 8 원칙의 Python 적용
| 원칙 | Python에서의 적용 |
|------|----------------------|
| 재귀 사용 제한 | 재귀 대신 반복문을 우선 검토. 재귀가 불가피하면(트리 순회 등) 최대 깊이를 주석으로 명시하고 `sys.setrecursionlimit` 남용을 피한다 |
| 포인터 사용 제한 | Python에는 명시적 포인터가 없으므로, 가변 객체(list/dict)의 참조를 통한 암묵적 공유·부작용을 제한하는 것으로 해석한다 — 함수는 인자로 받은 가변 객체를 예상치 못하게 변경하지 않는다(불변 데이터 선호, 필요 시 명시적으로 복사) |
| 동적 객체 생성 제한 | 실시간성이 중요한 반복 루프 내부에서 불필요한 객체 생성을 피한다(리스트/딕셔너리 컴프리헨션 남용 주의) |
| 은닉된 데이터/제어흐름 금지 | 데코레이터·메타클래스·모킹으로 인한 암묵적 동작 변경을 문서화 없이 사용하지 않는다 |
| 낮은 복잡도 유지 | `quality-metrics.md`의 순환복잡도 ≤10을 실측으로 강제(이 스킬의 필수 게이트) |
| 안전한 언어 서브셋 | `ruff`/`pylint` 린트 규칙 세트를 프로젝트 표준으로 삼아 위험 패턴(예: `eval`/`exec` 사용, 가변 기본 인자 `def f(x=[])`)을 차단한다 |
