# 함수 커버리지·Call 커버리지 100% 달성 절차 (Python)

Python 생태계에는 ISO 26262가 말하는 "Call 커버리지"를 그대로 리포트해주는 표준 오픈소스 도구가 따로 없다(임베디드 C/C++ 대상 상용 도구가 주로 이 지표를 제공한다). 이 스킬은 `coding` 스킬이 이미 쓰는 `coverage.py`(구문·분기 커버리지)를 기반으로, 함수 커버리지와 Call 커버리지를 **직접 도출**하는 방법을 정의한다.

## 1. 기반 데이터 수집 — `coverage.py` (구문·분기 커버리지)
```
coverage run --branch -m unittest discover -s tests
coverage json -o coverage.json   # 라인별 실행 여부를 프로그램적으로 읽기 위해 JSON으로 출력
```
`--branch` 옵션으로 분기 커버리지까지 함께 수집한다 — 조건문 안에 있는 호출 지점을 정확히 판정하는 데 필요하다.

## 2. 함수 목록·호출 지점 목록 추출 — Python `ast` 모듈
대상 소스 파일을 `ast.parse`로 분석해 다음 두 목록을 만든다(간단한 스크립트로 자동화 가능, 프로젝트에 `tools/coverage_check.py` 같은 이름으로 스크립트를 만들어 두는 것을 권장한다):
- **함수 목록**: 모든 `ast.FunctionDef`/`ast.AsyncFunctionDef` 노드와 그 첫 실행 라인 번호.
- **호출 지점 목록**: 모든 `ast.Call` 노드와 그 라인 번호(하나의 라인에 여러 호출이 있으면 개별적으로 구분 — 필요 시 열(column) 정보까지 사용).

## 3. 커버리지 데이터와 교차 대조
1의 `coverage.json`이 보고하는 "실행된 라인 번호" 집합과 2에서 추출한 두 목록을 대조한다:
- **함수 커버리지**: 각 함수의 첫 실행 라인이 "실행된 라인" 집합에 있으면 그 함수는 커버된 것으로 판정. `커버된 함수 수 / 전체 함수 수`.
- **Call 커버리지**: 각 호출 지점의 라인이 "실행된 라인" 집합에 있으면 그 호출은 실행된 것으로 판정(한 라인에 호출이 여럿이면 분기 커버리지 데이터나 조건부 실행 여부까지 함께 확인). `실행된 호출 지점 수 / 전체 호출 지점 수`.

## 4. 결과 해석과 반복
- 두 지표 모두 100%가 아니면, 커버되지 않은 함수/호출 지점 목록을 통합시험 케이스 설계(3~4단계, `iso26262-6-integration-test-methods.md`)의 입력으로 되돌린다.
- 어떤 통합 단계에서, 어떤 인터페이스를 통해 그 함수/호출을 실행할 수 있는지 `integration-sequence.md`와 인터페이스 명세를 다시 확인해 시험 케이스를 추가한다.
- 시험을 아무리 추가해도 도달할 수 없는 항목(예: 하드웨어 결함 없이는 진입 불가능한 방어 코드)이면, `iso26262-6-integration-test-methods.md`의 "도달 불가능성 근거 문서화" 절차를 따른다 — 코드 분석 또는 결함주입시험으로 도달 불가능함을 논증하고, 그 근거를 커버리지 보고서에 기록한다.
- 억지로 100%를 맞추기 위해 의미 없는 호출(예: 아무 의미 없는 파라미터로 함수를 한 번 호출만 하고 결과를 검증하지 않는 시험)을 추가하지 않는다 — `tdd` 스킬의 "테스트는 깨짐의 이름을 댈 수 있어야 한다" 원칙을 커버리지 지표에도 동일하게 적용한다.

## 5. 보고 형식
```
| 파일/컴포넌트 | 전체 함수 수 | 커버된 함수 수 | 함수 커버리지 | 전체 호출 지점 수 | 커버된 호출 지점 수 | Call 커버리지 | 미달 항목 |
```
미달 항목은 "함수/호출 지점 위치 — 사유(보강 예정/도달불가 근거)" 형태로 개별 기재한다.

## 참고 — 대안 도구
프로젝트 규모가 커지면 아래도 검토할 수 있다(선택 사항, 표준 도구는 아니므로 도입 시 사용자와 협의):
- `coverage.py`의 `Coverage.analysis2()` API를 직접 호출해 2~3단계 스크립트를 더 정교하게 만들 수 있다.
- `sys.settrace`/`sys.monitoring`(Python 3.12+)으로 함수 호출 이벤트를 직접 기록하면 호출 지점 단위 계측을 더 정밀하게 할 수 있다(성능 오버헤드는 커짐).
