# 기능요구사항의 UML/SysML 다이어그램화 가이드

다이어그램은 텍스트 요구사항을 **대체하지 않고 보완**한다. 모든 다이어그램 요소에는 대응하는 요구사항 ID를 라벨/주석으로 표기해 추적성을 유지한다(`traceability-scheme.md` 참조). 다이어그램 소스는 버전관리와 리뷰(diff)가 가능하도록 텍스트 기반 표기(PlantUML, Mermaid 등)를 기본으로 하고, 필요 시 렌더링된 이미지를 함께 첨부한다.

## 요구사항 성격별 다이어그램 선택 기준

| 요구사항 성격 | 권장 다이어그램 | 용도 |
|----------------|------------------|------|
| 액터(사용자/외부시스템)와 시스템 간 상호작용 범위 | UML 유스케이스 다이어그램(Use Case Diagram) | 기능 범위와 액터별 책임 정의 — 요구사항을 유스케이스 단위로 그룹핑 |
| 처리 절차·알고리즘·조건분기 흐름 | UML 액티비티 다이어그램(Activity Diagram) | 순서·병행·조건 로직을 가진 기능요구사항의 흐름 표현 |
| 컴포넌트/객체 간 메시지 교환 순서, 인터페이스 요구사항 | UML 시퀀스 다이어그램(Sequence Diagram) | 통신 순서, 타이밍 제약이 있는 인터페이스 요구사항 |
| 모드/상태 전이 기반 동작(특히 안전 관련) | UML/SysML 상태기계 다이어그램(State Machine Diagram) | 상태별 허용 동작, 전이 조건, 안전상태(safe state) 전이 요구사항 |
| 요구사항 간 계층 구조와 만족/파생/검증 관계 | SysML 요구사항 다이어그램(Requirement Diagram) | `«derive»`(파생), `«satisfy»`(설계요소가 요구사항을 만족), `«verify»`(테스트케이스가 요구사항을 검증) 관계로 추적성 시각화 |
| 시스템 구조·인터페이스에 요구사항을 할당 | SysML 블록정의 다이어그램(BDD) / 내부블록 다이어그램(IBD) | 기능을 시스템 블록/포트에 배분(allocate)하는 요구사항 |
| 파라미터 간 수식적 제약(성능/안전 관련 NFR 보조) | SysML 파라메트릭 다이어그램(Parametric Diagram) | 정량적 제약식을 가진 요구사항(주로 NFR 보조 설명용) |

같은 요구사항 집합에 여러 다이어그램을 함께 쓰는 것이 일반적이다. 예: 유스케이스 다이어그램으로 범위를 잡고, 각 유스케이스의 세부 흐름은 액티비티/시퀀스 다이어그램으로 상세화한다.

## 작성 원칙

1. **요구사항 ID 라벨 필수**: 다이어그램의 각 요소(유스케이스, 액션, 상태, 메시지 등)에 대응하는 요구사항 ID를 주석이나 스테레오타입으로 표기한다. 라벨이 없는 다이어그램 요소는 추적 불가능한 것으로 간주한다.
2. **표준 표기 준수**: 임의 기호를 만들지 않는다. UML/SysML 표준 표기를 따르되, 팀 내 통용되지 않는 확장 표기는 범례(legend)를 반드시 첨부한다.
3. **과도한 복잡도 지양**: 하나의 다이어그램에 너무 많은 요소를 넣지 않는다(이해가능성 저해). 유스케이스 다이어그램은 액터 3~7개, 시퀀스 다이어그램은 라이프라인 5개 내외를 권장 상한으로 삼고, 초과하면 하위 다이어그램으로 분할한다.
4. **다이어그램만으로 완결하지 않음**: 다이어그램은 텍스트 요구사항의 이해를 돕는 보조 수단이다. 다이어그램에만 존재하고 텍스트 요구사항 항목(ID 포함)이 없는 요건은 인정하지 않는다 — 반드시 텍스트 요구사항과 1:1 이상으로 연결되어야 한다.
5. **파일 관리**: 다이어그램 소스 파일은 요구사항 문서와 같은 디렉터리 또는 프로젝트가 정한 diagrams 디렉터리에 저장하고, 요구사항 항목의 "다이어그램 참조" 필드에 상대경로로 링크한다.

## 도구 예시 (텍스트 기반, 버전관리 친화적)
- PlantUML: 유스케이스, 액티비티, 시퀀스, 상태기계 다이어그램에 폭넓게 사용 가능하며 SysML 확장(`sysml` 라이브러리)도 지원.
- Mermaid: 시퀀스, 상태, 클래스 다이어그램을 마크다운 내에 바로 렌더링 가능(다만 SysML 전용 표기는 제한적).
- 정식 SysML 모델링 툴(예: Cameo, Capella)을 조직이 이미 사용 중이면 그 툴의 모델 파일을 원본으로 하고, 리뷰용으로 PlantUML/이미지 export본을 함께 둔다.
