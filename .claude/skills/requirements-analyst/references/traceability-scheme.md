# 양방향 추적성 스킴

> 근거: Automotive SPICE PAM 4.1 SYS.1.BP4, SYS.2.BP5/BP6, SWE.1.BP5/BP6 — "일관성을 확보하고 양방향 추적성을 수립한다(Ensure consistency and establish bidirectional traceability)"가 각 레벨의 필수 베이스프랙티스다. SYS.2 Note 7 / SWE.1 Note 11은 "추적 링크가 존재한다는 것 자체가 정보의 일관성을 의미하지는 않는다"고 명시한다 — 즉 링크만 걸어두는 것으로는 부족하고, 연결된 내용이 실제로 부합하는지 확인해야 한다.

## ID 채번 규칙

| 레벨 | 접두사 | 예시 | 대응 A-SPICE 프로세스/산출물 |
|------|--------|------|------------------------------|
| 이해관계자 요구사항 | `STK-####` | STK-0001 | SYS.1 (17-00 Requirement) |
| 시스템 요구사항 | `SYS-REQ-####` | SYS-REQ-0012 | SYS.2 (17-00, 17-54) |
| 소프트웨어 요구사항 | `SW-REQ-####` | SW-REQ-0034 | SWE.1 (17-00, 17-54) |

- 비기능요구사항은 ID에 ISO 25010 특성 태그를 접미사로 붙인다: `SW-REQ-0034-PERF`(성능효율성), `-SEC`(보안성), `-REL`(신뢰성), `-SAFETY`(안전성), `-MAINT`(유지보수성), `-COMPAT`(호환성), `-INTERACT`(상호작용역량), `-FLEX`(유연성).
- ID는 한 번 부여되면 재사용하지 않는다. 요구사항이 폐기되어도 ID는 "폐기(deprecated)" 상태로 남기고 삭제하지 않는다(이력 보존, 추적 무결성 유지).

## 링크 방향과 필드

모든 요구사항 항목에는 두 방향의 링크 필드를 둔다(템플릿의 "상위 추적" / "하위 추적" 필드, `template.md` 참조):

- **상위 추적(부모)**: 이 요구사항이 어떤 상위 요구사항/니즈에서 파생됐는지. 예: SW-REQ-0034의 부모는 SYS-REQ-0012.
- **하위 추적(자식)**: 이 요구사항이 어떤 하위 산출물(아키텍처 요소, 설계 요소, 테스트케이스, 코드 모듈)에 할당·검증되는지. 예: SYS-REQ-0012의 자식은 SW-REQ-0034, SW-REQ-0035, TC-0089.

두 방향 모두 채워야 "양방향" 추적이 성립한다. 한쪽만 있으면(예: 자식은 부모를 가리키는데 부모 쪽에 자식 목록이 없음) 불일치로 간주하고 즉시 보정한다.

## 추적매트릭스

프로젝트 내 단일 위치에 전체 추적 관계를 집계한 매트릭스를 둔다(권장 경로: `docs/traceability/trace-matrix.md`, 표 형태). 각 요구사항 항목의 상위/하위 링크를 수정할 때마다 이 매트릭스도 함께 갱신한다 — 개별 요구사항 문서와 매트릭스가 어긋나면 안 된다.

```
| ID | 유형 | 상위 추적 | 하위 추적 | 커버리지 상태 |
|----|------|-----------|-----------|----------------|
| STK-0001 | 이해관계자 | (최상위) | SYS-REQ-0012 | OK |
| SYS-REQ-0012 | 시스템 | STK-0001 | SW-REQ-0034, SW-REQ-0035 | OK |
| SW-REQ-0034 | 소프트웨어 | SYS-REQ-0012 | TC-0089 | OK |
| SW-REQ-0036 | 소프트웨어 | SYS-REQ-0012 | 미배정 | 갭(하위 산출물 없음) |
```

## 점검해야 할 이상 패턴

- **고아 요구사항(Orphan)**: 상위 추적이 없는 시스템/소프트웨어 요구사항(최상위인 이해관계자 요구사항 제외). 왜 존재하는지, 어떤 상위 요구에서 파생됐어야 하는지 확인한다.
- **커버리지 갭(Coverage gap)**: 하위 추적이 없는 요구사항 — 아직 설계/테스트로 이어지지 않았다는 뜻이다. 프로젝트 단계상 아직 이르면 "미배정"으로 명시하고, 이미 지나간 단계라면 결함으로 보고한다.
- **중복 추적**: 동일한 하위 산출물이 서로 모순되는 두 상위 요구사항에 동시에 연결된 경우 — 일관성 점검(SKILL.md 6단계) 대상.
- **끊어진 링크**: ID가 매트릭스나 문서 어디에도 존재하지 않는 경우(오탈자, 삭제된 항목 참조). 발견 즉시 수정한다.

## 다이어그램과의 연계
UML/SysML 다이어그램을 사용하는 기능요구사항의 경우, 다이어그램 요소(유스케이스, 블록, 상태 등)에 대응하는 요구사항 ID를 라벨이나 주석으로 표기한다. SysML을 쓸 수 있는 환경이면 `«satisfy»`, `«derive»`, `«verify»` 관계로 요구사항 다이어그램에 직접 추적 관계를 시각화할 수 있다 — 이 경우에도 텍스트 기반 추적매트릭스는 별도로 유지한다(다이어그램 툴이 없는 리뷰어·감사자도 확인할 수 있어야 하기 때문).
