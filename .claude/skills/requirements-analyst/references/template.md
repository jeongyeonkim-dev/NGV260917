## TPL-SWE1-001 — SW 요구사항 명세서 목차
0. 문서 통제(작성/검토/승인 상태, 변경이력) — 실제 승인 여부와 검토 증거 위치를 구분해 기록
1. 목적 및 적용범위 (1.1 목적 / 1.2 적용범위 / 1.3 적용 경계)
2. 요구사항 작성 및 판정 규칙 (2.1 식별·상태 규칙 / 2.2 품질 판정 기준 — 명확성·원자성·일관성·검증가능성·추적성)
3. 상태와 우선순위
4. 기능 및 안전 관련 SW 요구사항 (4.1 기능 요구사항 / 4.2 안전 관련 SW 요구사항 — 상위 안전요구 출처·할당 근거 유지)
5. 입력 데이터 사전 (명칭/자료형/단위/범위/유효성조건/오류처리)
6. 외부 인터페이스 요구
7. 비기능 및 환경 제약 (측정 가능한 기준으로)
8. 분석 결과와 가정 (가정/의존성/상충사항/미결정)
9. 하향 할당 및 검증 계획 (요구사항별 설계 할당 대상, 검증 수준·방법·계획된 증거)
10. 범위 밖 주장 (이 문서만으로 주장할 수 없는 시험수준·인증·적합성 범위)
11. 추적성
12. 참고자료

각 요구사항 항목(4절)은 이 스킬의 필드(ID/유형/레벨/출처/설명/수용기준/검증방안/다이어그램참조/상위추적/하위추적/우선순위/상태)를 4절 표의 컬럼으로 매핑해 작성한다.

## TPL-TRC-001 — 양방향 추적 매트릭스 (전 스킬 공통, 아래 컬럼 그대로 사용)
시트 "Bidirectional Trace"의 컬럼: **Upper Req | SW Req | Architecture | Detailed Design | Code | SWE.4 | SWE.5 | SWE.6 | Coverage**

- 이 9개 컬럼이 `traceability-scheme.md`가 정의하는 추적매트릭스의 정식 형식이다 — 이전에 이 스킬이 예시로 쓰던 5컬럼(ID/유형/상위추적/하위추적/커버리지상태) 표는 폐기하고 이 9컬럼을 쓴다.
- "SW Req" 컬럼에는 이 프로젝트가 채택한 ID(`SWR-001`~`SWR-021`, `traceability-scheme.md` 참조)를 쓴다.
- 시트 "Change History"의 컬럼: Revision | 변경일 | 작성 역할 | 변경 내용 | 검토 상태 | 승인 상태.

## 사용 지침
- 각 요구사항 산출물의 "작성 안내" 문구(템플릿 원본의 이탤릭 안내문)는 최종본에서 실제 내용으로 교체하고 안내문 자체는 남기지 않는다.
- 문서 통제 절의 "실제 승인" 상태는 이 프로젝트의 실제 승인 여부를 정직하게 기록한다(교육용 원본 템플릿의 문구를 그대로 복사하지 않는다).
